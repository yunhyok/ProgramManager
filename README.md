# Program Manager 0.4.4

0.4.4에서는 **호스트 관리**의 중복 **호스트 설정** 버튼을 제거했습니다. 주소·계정·연결 코드는 상단 **설정 → 호스트 · 배포**에서 관리합니다.

빌드와 화면 확인 결과는 [0.4.4 검증 기록](docs/verification-0.4.4.md)에 있습니다.

0.4.3에서는 **오프라인 설명**에 HTML 태그가 그대로 보이던 문제를 수정했습니다. README와 릴리스 본문의 HTML·Markdown 제목, 목록, 표, 강조를 서식으로 표시하고 코드 예제는 원문대로 유지합니다. 호스트를 업데이트한 뒤 설명을 다시 열면 이전 설명 캐시를 새 형식으로 생성합니다.

실제 문서 표시와 캐시 갱신 확인은 [0.4.3 검증 기록](docs/verification-0.4.3.md)에 있습니다.

Windows 선택 목록·검색창·버튼의 높이와 정렬 기준을 통일했습니다. 선택 탭과 주요 작업을 강조하고, 목록·설명 영역의 여백과 색상을 정리했습니다. 작은 창에서도 프로그램 설명 영역을 유지합니다.

0.4.2에서는 **클라이언트의 목록 새로고침 → 호스트의 GitHub 조회 → 최신 배포 목록 전달** 순서로 갱신합니다. 호스트와 클라이언트를 모두 0.4.2 이상으로 업데이트하세요. 일부 조회가 실패하면 기존 배포 정보를 유지하고 카탈로그에 안내를 표시합니다. 설치 파일은 설치를 요청할 때만 받습니다.

**설정 → 일반**에서 호스트 역할을 끄면 메인 화면에는 **내 프로그램 / 배포 카탈로그**만 표시됩니다. 호스트 관리 탭과 배포용 버튼은 역할을 켤 때만 나타납니다. 목록 갱신 후 설치·업데이트 버튼이 비활성화된 채 남는 문제도 수정했습니다.

개인 개발 프로그램을 트레이의 목록에서 실행하고, GitHub Releases의 프로그램을 내부망 PC에 배포하는 Windows 앱입니다. **호스트에서 배포할 저장소를 선택하면 클라이언트는 그 목록에서 설치합니다.** 인터넷이 없는 클라이언트도 사용할 수 있습니다.

설치 파일은 설치 요청이 있을 때 호스트가 다운로드합니다. 설명과 릴리스 이력도 요청할 때 HTML로 만들어 전달합니다. 사용하지 않은 임시 파일은 주기적으로 정리하며, 기존에 등록한 실행 목록은 그대로 유지합니다.

## 어디에서 무엇을 하나요?

| 화면 | 용도 | 처음 할 일 |
| --- | --- | --- |
| **내 프로그램** | 이 PC에 설치된 프로그램 실행·목록 정리 | 기존 항목을 선택해 **실행**, 필요한 EXE/LNK만 추가 등록 |
| **배포 카탈로그** | 호스트가 공유한 프로그램 설명 확인·설치·업데이트 | **연결 설정**에서 호스트 연결 |
| **호스트 관리** | 배포할 GitHub 저장소 선택·릴리스 목록 동기화 | **설정 → 호스트 · 배포**에서 배포 준비 |

호스트도 같은 앱에서 자신의 프로그램을 설치할 수 있습니다. 창을 닫으면 트레이에 남으며, 트레이 메뉴의 **종료**로 완전히 종료합니다.

트레이 아이콘을 **오른쪽 클릭**하면 메뉴 맨 위에 최근 실행한 프로그램이 최대 5개 표시됩니다. 항목을 클릭하면 바로 실행합니다. Manager에서 실행한 등록 프로그램만 중복 없이 최근 순서로 기록하며, Manager를 다시 실행해도 유지합니다. 등록 이름·경로를 편집하면 최근 항목에도 반영되고, 등록을 제거하면 최근 목록에서도 사라집니다. 과거 실행 이력은 자동으로 채우지 않으므로 처음에는 비어 있습니다.

## 설정은 어디에서 하나요?

| 설정 탭 | 설정하는 내용 | 입력할 값 |
| --- | --- | --- |
| **일반** | 이 PC의 역할, 로그인 시 자동 실행, 설치된 앱 및 Manager 새 버전 자동 확인 | 배포할 PC는 **다른 PC에 프로그램 배포 (호스트)** 체크, 설치만 할 PC는 체크 해제 |
| **호스트 · 배포** | 이 호스트의 내부망 주소·포트, GitHub 설정, 연결 코드 생성·복사 | 네트워크 어댑터에서 고른 이 PC의 LAN IP 또는 클라이언트가 찾을 수 있는 호스트 이름. 기본 TCP 포트 `45672` |
| **클라이언트 · 연결** | 받은 연결 코드 입력, 연결 대상 표시, 연결 확인 | 호스트에서 복사한 `PM1:`로 시작하는 문자열 전체 |

호스트 주소에는 **배포하는 PC의 주소**를 넣습니다. 클라이언트 IP나 연결 코드를 넣는 칸이 아닙니다. 포트는 호스트가 연결을 받는 번호이며 특별한 사유가 없으면 기본값을 사용합니다. 클라이언트는 별도 IP·포트를 입력하지 않습니다. 연결 코드는 직접 정하는 비밀번호가 아니라 호스트가 자동 생성하는 값입니다.

호스트 설정은 상단 **설정 → 호스트 · 배포**에서 엽니다. **연결 설정**은 **클라이언트 · 연결** 탭을 바로 엽니다. **연결 코드 생성 · 복사**는 **설정 → 호스트 · 배포** 안에 있습니다. 역할이 클라이언트이면 호스트 옵션은 이유 안내와 함께 비활성화되므로, 배포하려면 **일반** 탭에서 역할을 먼저 바꾸세요.

**연결 확인**은 접속 결과만 조회하며 설정을 저장하지 않습니다. **설정 적용**으로 변경을 저장하세요. **연결 코드 생성 · 복사**도 현재 설정을 적용한 뒤 호스트를 시작·확인합니다. 적용하지 않고 설정 창을 닫으면 변경은 버립니다. 별도 GitHub 설정 창의 **저장**은 해당 계정·임시 파일 옵션을 즉시 적용합니다. 기존 연결을 끊으려면 **클라이언트 · 연결**의 **연결 해제**를 체크하고 **설정 적용**을 누릅니다.

## 빠른 시작

**개발 PC / 호스트 — 인터넷과 내부망 연결이 있는 PC**

1. **설정 → 일반**에서 **다른 PC에 프로그램 배포 (호스트)**를 체크합니다. **호스트 · 배포**에서 클라이언트와 같은 내부망에 연결된 네트워크 어댑터의 주소와 포트를 확인하고 **설정 적용**을 누릅니다.
2. **호스트 · 배포 → GitHub 및 임시 파일 설정**에서 계정을 연결합니다. 메인 화면의 **호스트 관리 → 저장소 선택**에서 배포할 프로그램을 고르고 **선택한 저장소 동기화**를 누릅니다. 이후에는 **GitHub 동기화**로 새 버전을 확인합니다.
3. **설정 → 호스트 · 배포**로 돌아와 **연결 코드 생성 · 복사**를 누릅니다. 현재 설정 적용, 호스트 시작과 주소 연결 확인에 성공하면 읽기 전용 `PM1:` 코드를 생성하고 복사합니다. 사용할 PC에 전체 코드를 전달하세요. 주소·포트를 바꾸면 이 버튼으로 새 코드를 생성해 클라이언트에도 다시 등록합니다. 호스트 이름을 찾지 못하면 현재 LAN IP를 선택해 다시 시도하세요.

**사용 PC / 클라이언트 — 인터넷 연결 불필요**

1. **배포 카탈로그 → 연결 설정**을 엽니다. **클라이언트 · 연결** 탭의 **호스트에서 받은 연결 코드**에 `PM1:` 문자열 전체를 붙여 넣고 표시된 연결 대상을 확인합니다. GitHub 인증 정보나 클라이언트 IP·포트는 입력하지 않습니다.
2. **연결 확인**을 눌러 연결 결과와 카탈로그 프로그램 수를 확인한 뒤 **설정 적용**을 누릅니다. 연결 정보가 저장되며 **배포 카탈로그**를 자동으로 새로 고칩니다.
3. 카탈로그에서 프로그램을 선택해 **오프라인 설명**을 읽고 **설치 / 업데이트**를 진행합니다. 설치가 끝나면 실행 경로와 실제 설치 버전을 찾아 **내 프로그램**에 자동 등록합니다. 후보가 여러 개이거나 설치 결과를 확인할 수 없을 때만 확인 화면을 표시합니다.

카탈로그는 **설치 가능한 프로그램 목록**입니다. 연결 전에는 **연결 설정**을 사용하고, 연결됐지만 목록이 비어 있으면 호스트에서 저장소 선택·동기화를 확인하세요. 이미 설치한 앱은 **내 프로그램**에서 계속 실행할 수 있습니다. 일반 GitHub 배포는 클라이언트 0.2.0 이상과 호환되며, 위 설정 탭 구성은 0.4.2 기준입니다.

자세한 사용법과 문제 해결은 앱의 **도움말** 또는 [설치에 포함되는 오프라인 도움말](docs/guide.html)을 참고하세요. 배포 규칙과 운영 예시는 [GitHub 배포 안내](docs/github-distribution.md)에 있습니다.

**도움말**과 **오프라인 설명**은 Program Manager 안에서 열리므로 별도의 브라우저가 필요하지 않습니다.

## 설치

| 컴퓨터 | 설치 파일 | 런타임 |
| --- | --- | --- |
| Windows 10/11 64비트 | `ProgramManager-Setup-0.4.4.exe` | .NET 8 포함 |
| Windows 7 SP1 / 8 계열 | `ProgramManager-Setup-0.4.4-win7.exe` | .NET Framework 4.8 사전 설치 필요 |

기본 설치 위치는 `%LOCALAPPDATA%\Programs\Program Manager`입니다. 시작 메뉴에서 실행할 수 있고, 바탕화면 바로가기는 기본으로 만들지 않습니다. Windows 로그인 시 자동 실행은 설치 옵션 또는 앱 설정에서 선택합니다.

이미 등록한 프로그램의 설치 위치와 실행 경로는 유지됩니다. **목록에서 제거**는 대상 프로그램을 삭제하지 않습니다. `.lnk` 등록 시에는 Manager 데이터 폴더에 바로가기를 복사하므로 실행을 확인한 후 바탕화면 바로가기를 정리할 수 있습니다. 대상 EXE 파일 자체는 원래 위치에 두세요.

## 설치된 앱 자동 등록과 업데이트 알림

0.4.0부터 설치 프로그램이 완료되면 Windows의 설치 기록, 시작 메뉴 바로가기와 실행 파일 정보를 읽습니다. 실행 경로와 요청한 버전의 설치가 확인되면 자동 등록하며, 기존 항목과 같은 실행 파일이면 이름·바로가기 실행 옵션을 유지합니다. 취소·실패·버전 미확인을 최신 버전 설치로 기록하지 않습니다.

이미 설치했지만 등록하지 않은 앱은 **배포 카탈로그 → 기존 설치 연결**을 누르면 자동으로 찾습니다. 여러 후보가 있거나 설치 기록이 없는 앱은 실행 경로를 직접 확인합니다. 버전을 모르면 비워 두세요.

등록된 앱은 시작할 때와 **1시간마다**, 또는 **목록 새로고침** 때 실제 설치 버전과 호스트의 배포 버전을 비교합니다. 기본으로 켜져 있으며 **설정 → 일반 → 설치된 앱 업데이트**에서 주기적 확인을 끌 수 있습니다. 이름과 실행 경로가 확인되는 기존 등록 항목도 배포 목록에 연결합니다. 목록에서 제거한 앱을 백그라운드에서 다시 추가하지 않습니다.

새 버전이 있으면 트레이 아이콘에 주황색 화살표가 표시되고, 알림과 **업데이트 N개** 메뉴에서 **현재 버전 → 새 버전**을 확인할 수 있습니다. 항목을 누르면 해당 배포 앱을 선택하며 **설치 / 업데이트**로 진행합니다. 동일한 업데이트 목록의 알림은 반복하지 않으며, 실제 설치 버전이 갱신되면 표시가 사라집니다. 자동 확인만으로 다운로드하거나 설치하지 않습니다. 인터넷이 없는 클라이언트도 연결된 호스트의 목록을 사용합니다.

버전은 Windows 설치 기록의 `DisplayVersion`을 우선 사용하고 없으면 실행 파일의 제품·파일 버전을 읽습니다. 버전 정보가 없거나 앱 자체 버전과 다른 값이 기록된 프로그램은 **편집**에서 확인이 필요할 수 있습니다. Windows에서 알림이 숨겨져도 트레이 메뉴는 사용할 수 있습니다.

## Program Manager 자체 업데이트

0.3.0부터 Manager가 시작할 때와 실행 중 **6시간마다** 새 버전을 확인합니다. 자동 확인은 기본으로 켜져 있으며 **설정 → 일반**에서 끌 수 있습니다. 새 버전마다 트레이 알림을 한 번 표시합니다. Windows 알림 설정에 따라 알림이 보이지 않아도 트레이 메뉴는 사용할 수 있습니다.

1. 트레이 아이콘을 오른쪽 클릭하고 **업데이트 확인**을 선택합니다. Program Manager 자체와 호스트가 배포하는 설치된 앱을 함께 확인합니다. 호스트·클라이언트 역할별로 Manager를 따로 업데이트하지 않습니다.
2. 새 버전이 있으면 **업데이트 N개** 안에서 **Program Manager 현재 버전 → 새 버전 · 업데이트 및 재시작**을 선택하고 설치를 확인합니다. 다른 앱도 같은 메뉴 안에 이름·버전으로 표시됩니다. 업데이트가 없으면 이 메뉴는 숨겨집니다.
3. 진행 상태를 보며 다운로드를 기다립니다. 크기·SHA-256 검증이 끝나면 Manager를 종료하고 설치한 뒤 기존 데이터로 다시 시작합니다. 새 버전 확인이나 알림 표시만으로 설치하지 않으며, 사용자가 업데이트 실행을 선택하고 확인해야 진행합니다.

호스트에 연결된 클라이언트는 **0.3.0 이상 호스트**를 통해 Manager 업데이트를 받아 인터넷 없이 사용할 수 있습니다. 호스트가 이전 버전이면 호스트부터 업데이트하세요. 호스트 PC와 호스트에 연결되지 않은 PC는 공개 저장소 [yunhyok/ProgramManager](https://github.com/yunhyok/ProgramManager)의 Releases를 직접 조회하며 추가 GitHub 인증 정보가 필요하지 않습니다.

Manager의 새 버전 확인에는 호스트의 인터넷 연결이 필요합니다. 설치 전에 기존 Manager 파일을 임시 백업하고, 설치가 실패하면 이전 파일을 복구한 뒤 다시 실행합니다. 복구까지 실패하면 설치 로그와 수동 복구 안내를 표시합니다. 등록 목록과 설정 데이터는 이 파일 교체 대상에 포함하지 않습니다.

숫자 태그의 정식 Release에서 이 PC의 Windows에 맞는 Manager 설치 파일만 사용합니다. Windows 7용 파일이 없으면 Windows 10/11용 파일을 대신 제안하지 않습니다. 일반 프로그램의 GitHub 배포에 필요한 최소 클라이언트 버전은 계속 0.2.0입니다.

## 배포 동작

- **저장소 선택**은 Release와 설치 파일의 메타데이터를 먼저 검사해 상태·사유를 표시합니다. 설치 파일 자체는 받지 않습니다. 검사·동기화 중에는 화면 하단에 저장소 이름과 처리 수/전체 수가 표시됩니다.
- 배포할 수 없는 새 저장소는 선택할 수 없습니다. 파일 후보가 모호하면 Windows별 파일 이름 패턴을 수정하고 **다시 검사**합니다. 이미 선택했던 저장소가 검사에 실패해도 체크는 유지되며, 체크를 해제해 배포 대상에서 뺄 수 있습니다.
- 동기화는 정상 저장소를 갱신하고 실패 사유를 따로 요약합니다. 실패한 저장소에 이전 게시 항목이 있으면 유지합니다. 동기화를 취소하면 현재 게시 목록을 유지합니다.
- 배포 버전은 `v1.2.3` 같은 숫자 태그의 정식 **Releases**를 기준으로 합니다. 조회한 최근 100개 Release 중 정식 버전을 최대 30개 가져옵니다. 브랜치의 최신 커밋, Draft, Prerelease, 소스 ZIP은 설치 대상으로 사용하지 않습니다. 권한이 있는 비공개 저장소도 사용할 수 있습니다.
- Windows 10/11용과 Windows 7용 EXE/MSI 설치 파일을 별도로 선택합니다. 자동 판별이 모호하면 저장소별 파일 이름 패턴을 지정합니다. Windows 7용이 없으면 다른 OS용 파일로 대체하지 않습니다.
- 목록 동기화는 메타데이터를 가져옵니다. 설치 파일 전체를 미리 받지 않으며, 설치 요청 시 필요한 파일을 받아 검증하고 캐시합니다.
- **설명 / 이력**은 이미 동기화한 메타데이터를 보여줍니다. **오프라인 설명**은 요청 시 README와 릴리스 이력을 자체 포함 HTML로 만듭니다. 제목·본문·코드 블록을 표시하며, 복잡한 서식과 링크는 텍스트로 남습니다. 외부 웹사이트·이미지·첨부파일은 자동 복제하지 않습니다.
- 설명 캐시는 날짜가 바뀌어도 재사용합니다. 동기화한 프로그램·릴리스 정보가 바뀌거나 캐시가 정리되면 다음 요청 때 새로 받습니다. README만 바뀐 경우 **임시 파일 정리** 후 **오프라인 설명**을 다시 엽니다.
- 임시 파일은 기본 7일간 사용하지 않으면 정리 대상이 됩니다. 보관 기간은 **GitHub 설정**에서 1~30일로 정합니다. 앱 시작 시와 실행 중 매시간 정리하며, 수동 정리는 사용 중인 파일을 건너뜁니다. 설치된 프로그램·설정·배포 목록은 정리 대상이 아닙니다.
- 클라이언트는 인증서 지문을 확인하는 TLS 1.2 연결로 호스트에 접근합니다. GitHub 인증 정보는 호스트에서만 사용하며 클라이언트에 전달하지 않습니다.

호스트 사용자가 로그인해 있고 Program Manager가 실행 중이어야 파일을 제공할 수 있습니다. 기본 TCP 포트는 `45672`입니다. 같은 내부망에서 접근 가능하도록 호스트 주소와 Windows 방화벽 설정을 확인하세요. 연결 코드에는 공유 비밀이 포함되므로 사용할 PC에만 전달합니다.

## 데이터와 실행 옵션

기본 데이터 폴더는 `%LOCALAPPDATA%\ProgramManager`입니다.

| 경로 | 내용 | 임시 파일 정리 |
| --- | --- | --- |
| `settings.json`, `shortcuts\` | 설정·로컬 실행 목록·복사된 바로가기 | 유지 |
| `repository\`의 메타데이터 | 호스트 배포 목록·릴리스 정보 | 유지 |
| `identity\` | 보호된 호스트 인증 정보 | 유지 |
| `repository\temp\` | 호스트의 설치 파일·설명 캐시 | 정리 대상 |
| `temp\` | 클라이언트의 임시 다운로드·설명 | 정리 대상 |
| `cache.json` | 마지막으로 확인한 호스트 목록 | 유지 |

직접 입력한 GitHub 토큰과 호스트 연결 정보는 Windows 사용자 계정으로 보호됩니다. 다른 PC나 Windows 계정에는 인증 정보를 다시 설정하세요. 제거 프로그램은 사용자 데이터 폴더를 삭제하지 않습니다. 임시 파일 정리는 Windows의 전체 Temp 폴더를 비우지 않습니다.

```powershell
# 창을 띄우지 않고 트레이에서 시작
ProgramManager.exe --tray

# 별도의 데이터 폴더로 실행 (개발 및 분리된 로컬 확인용)
ProgramManager.exe --data-dir "C:\Temp\ProgramManager-check"
```

## 빌드와 검증

통합 업데이트 메뉴는 [0.4.1 검증 기록](docs/verification-0.4.1.md), 자동 등록·버전 비교는 [0.4.0 검증 기록](docs/verification-0.4.0.md)에 있습니다.

클라이언트 요청에 따른 GitHub 갱신, 역할별 화면과 설치 버튼 수정은 [0.4.2 검증 기록](docs/verification-0.4.2.md)에 있습니다.

Windows, .NET SDK 8, Inno Setup 6.3 이상 6.x가 필요합니다. .NET Framework 참조 어셈블리는 NuGet으로 복원합니다. Windows 7용 설치 프로그램 호환성을 위해 Inno Setup 6을 사용합니다.

```powershell
./tools/build.ps1

# 컴파일러가 기본 경로에 없을 때
./tools/build.ps1 -InnoCompiler "C:\Tools\Inno Setup 6\ISCC.exe"
```

스크립트는 두 대상 프레임워크의 빌드와 검사를 실행한 뒤 아래 결과물을 만듭니다. 게시 출력 폴더 두 곳은 빌드할 때 새로 생성합니다.

| 출력 | 위치 |
| --- | --- |
| Windows 10/11 실행 파일 및 런타임 | `artifacts/publish/win10-x64/` |
| Windows 7용 실행 파일 및 의존 파일 | `artifacts/publish/win7/` |
| 두 설치 파일 및 `SHA256SUMS.txt` | `artifacts/installers/` |

`.github/workflows/build.yml`은 Windows 빌드·검사 후 두 설치 파일과 `SHA256SUMS.txt`를 버전별 Actions 아티팩트로 보관합니다. 공개 저장소 `yunhyok/ProgramManager`에 프로젝트 버전과 일치하는 `v` 태그를 push하면, 성공한 빌드의 세 파일만 GitHub Release로 게시합니다. 게시 전 원격 태그의 커밋과 설치 파일 해시를 확인합니다. 일반 브랜치 push·Pull Request·수동 실행은 Release를 게시하지 않습니다.

자체 업데이트의 확인 범위는 [0.3.0 검증 기록](docs/verification-0.3.0.md)을 참고하세요. 이전 결과는 [0.2.2 저장소 검사·동기화](docs/verification-0.2.2.md), [0.2.1 최근 실행 메뉴](docs/verification-0.2.1.md), [0.2.0 GitHub 배포](docs/verification-0.2.0.md), [0.1.1 UI](docs/verification-0.1.1.md), [0.1.0 배포](docs/verification.md)에 있습니다. Windows 7 실기기와 두 번째 물리 PC에서의 설치·통신은 별도 확인이 필요합니다. 최신 Windows에서 `net48`을 실행한 결과만으로 Windows 7 호환성을 확정하지 않습니다.

설치 결과를 하나로 확인할 수 없는 제품은 사용자가 실행 경로와 버전을 확인합니다. 배포 프로그램의 원격 무인 설치·자동 롤백, 호스트 자동 검색, Windows 서비스와 인터넷 중계는 제공하지 않습니다.

## IntraDrop 통합

현재 구현은 IntraDrop의 트레이 실행, 사용자별 설정과 인증된 연결 방식을 참고합니다. 카탈로그·다운로드 로직은 `src/ProgramManager.Core`, 화면은 WinForms 앱에 있습니다. 향후 IntraDrop과 통합할 때 공통 코어를 사용할 수 있으며, 현재 두 앱의 데이터와 실행은 독립적입니다.
