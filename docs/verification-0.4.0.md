# Program Manager 0.4.0 검증

검증일: 2026-09-10. 변경 범위는 설치 후 자동 등록, 실제 설치 버전 확인, 배포 앱 업데이트의 트레이 표시와 설정·도움말입니다.

## 구현 확인

- Windows 사용자/컴퓨터의 32·64비트 설치 기록을 읽고 시작 메뉴 바로가기 또는 실행 파일로 연결합니다. 설치 버전 기록이 없으면 실행 파일의 버전 정보를 사용합니다.
- 설치 프로그램 종료 코드만으로 성공을 기록하지 않습니다. 실제 실행 파일과 요청 버전 이상의 설치가 확인되어야 자동 등록합니다. 취소·실패·버전 미확인·복수 후보는 별도 확인이 필요합니다.
- 기존 실행 항목의 ID·이름·바로가기 옵션을 보존하고, 안정적인 설치 기록으로 경로 변경을 확인합니다. 다른 앱의 넓은 설치 폴더에서 버전을 가져오지 않습니다.
- 등록된 앱은 시작 시·매시간·수동 새로고침 때 버전을 확인합니다. 설치 버전이 낮은 현재 Windows용 앱만 트레이 아이콘 표시와 업데이트 메뉴에 포함합니다. 실제 설치 버전이 갱신되면 표시를 해제합니다.
- 자동 확인은 파일 다운로드나 설치를 실행하지 않습니다. 목록에서 제거한 앱을 백그라운드에서 다시 추가하지 않습니다.

## 실행한 검사

`tools/build.ps1` 전체가 로컬에서 성공했습니다.

| 검사 | 결과 |
| --- | --- |
| 앱 컴파일: net8.0-windows / net48 | 성공, C# 경고·오류 0개 |
| Core 및 Desktop 검사: 두 런타임 | 성공 |
| 새 설치 인식 검사 | 실제 설치 기록 읽기, 실행 파일 메타데이터, 버전 미확인·취소·복수 후보, 바로가기 옵션 보존, 경로 변경, 저장 버전 갱신, 트레이 선택·표시 해제 확인 |
| 화면 검사: 두 런타임 | 현재 모니터 DPI와 100/125/150/200/250% 시뮬레이션 모두 성공; 생략 0개 |
| 교차 런타임 TLS | net8 호스트→net48 클라이언트 및 역방향 카탈로그·두 플랫폼 파일 전송 성공 |
| 설치 파일 | 현대 Windows용·Windows 7용 EXE 및 SHA256SUMS 생성 |

네이티브 WinForms 렌더링으로 설정의 역할별 탭·새 업데이트 옵션, 트레이 화살표 및 `현재 버전 → 새 버전` 메뉴를 확인했습니다. 로컬 자료는 `artifacts/layout/`, `artifacts/tray-0.4.0/`에 있습니다.

현재 PC의 읽기 전용 설치 목록 검사에서도 9개 배포 항목 중 6개의 설치 경로와 버전을 확인했습니다. 찾지 못한 항목은 임의로 연결하지 않았습니다. 시점이 다른 두 번의 조회에서 외부 업데이트된 IntraDrop의 실제 설치 버전 변경도 반영됐습니다.

## 보안 프로그램 알림과 검사 변경

초기 검사에서 임시 EXE 복제와 임시 설치 레지스트리 작성을 시도하는 동안 V3 알림이 발생했습니다. 대상 파일의 해시가 검사 실행 파일과 일치함을 확인했습니다. 최종 검사는 기존 실행 파일과 메모리 내 설치 기록을 사용하며, 설치 레지스트리를 쓰거나 시험 EXE를 복제하지 않습니다. 수정한 검사는 두 런타임에서 정상 종료됐고, 보안 프로그램의 설정이나 예외 목록은 변경하지 않았습니다. 시험 파일은 배포 설치 파일에 포함되지 않습니다. 이 확인은 보안 제품의 진단을 무효화하거나 컴퓨터 전체의 무해성을 판정한 결과는 아닙니다.

## 범위

실제 Windows 7 장비 및 두 번째 물리 PC 검사는 별도입니다. net48 검사는 현재 Windows에서 실행했습니다. 제품에 버전 정보가 없거나 GitHub 항목과 설치 제품명이 다른 경우에는 수동 확인이 필요할 수 있습니다.

릴리스는 [v0.4.0](https://github.com/yunhyok/ProgramManager/releases/tag/v0.4.0)의 태그 빌드로 게시하며, 공개 설치 파일은 해당 릴리스의 SHA256SUMS와 함께 확인합니다.

- 설치된 앱의 접근성 트리에서 `Program Manager 0.4.0`, 등록 19개를 확인했습니다. 실제 LAN 주소를 통한 인증된 카탈로그 수신도 9개로 성공했습니다.
