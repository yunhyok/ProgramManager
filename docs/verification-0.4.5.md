# Program Manager 0.4.5 검증 기록

공통 영역에 있던 검색창과 새로고침을 각 목록 탭 안으로 옮겼습니다. 세 검색어는 각각 유지되며 다른 목록을 필터링하지 않습니다.

| 탭 | 갱신 동작 |
| --- | --- |
| 내 프로그램 | **설치 정보 새로고침**으로 이 PC의 설치 정보를 읽고 받아 둔 배포 정보와 비교합니다. 호스트에 요청하지 않습니다. |
| 배포 카탈로그 | **목록 새로고침**으로 연결된 호스트에 최신 배포 목록을 요청합니다. |
| 호스트 관리 | **GitHub 동기화**로 이 PC에서 배포하는 저장소를 갱신합니다. 같은 기능의 별도 새로고침 버튼은 추가하지 않았습니다. |

기존 폼과 검사를 재사용했습니다. 세 목록에 서로 다른 항목과 검색어를 넣어 검색 범위와 탭 이동 후 유지 여부를 확인합니다. 실제 TLS 검사 호스트의 요청 횟수로 로컬 갱신은 호스트 요청 0회, 카탈로그 갱신은 1회인 것을 확인했습니다. 트레이에서 업데이트 항목을 열 때 카탈로그 검색어만 지우고 다른 검색어는 유지합니다.

클라이언트 모드에서 호스트 역할을 나중에 켤 때 검색창의 너비가 DPI 배율을 따르지 않던 문제도 수정했습니다. 도구 모음의 고정 너비 입력칸에 배율을 적용하며, 설정 창처럼 레이아웃에 맞춰 늘어나는 입력칸의 너비는 유지합니다.

현재 Windows에서 .NET 8 및 .NET Framework 4.8 빌드, 코어·데스크톱 검사, 양방향 런타임 통신 검사가 통과했습니다. 실제 배율과 100/125/150/200/250% 모의 배율 검사에서 검색창 너비, 버튼 정렬 및 화면 배치를 확인했고 건너뛴 배율은 없습니다. 실제 폼의 세 탭 렌더링도 확인했습니다. Windows 7 실기기 실행 결과는 아닙니다.

로컬 전체 로그는 `artifacts/build-0.4.5-final.log`, 배율별 화면과 결과는 `artifacts/layout/`에 있습니다.
