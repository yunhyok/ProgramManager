# Program Manager 0.3.0 검증 기록

검증일: 2026-09-10. Windows 10 Pro 64비트, .NET 8 및 .NET Framework 4.8 환경.

## 자체 업데이트

- 시작 시 및 실행 중 6시간마다 확인하며, 설정에서 자동 확인을 끌 수 있습니다.
- 트레이에서 수동 확인과 새 버전의 업데이트 및 재시작을 선택할 수 있습니다. 새 버전의 알림 기록은 숫자 버전 기준으로 한 번 저장됩니다.
- 공개 `yunhyok/ProgramManager` 정식 Release 중 현재 Windows에 맞는 설치 파일만 선택합니다. 다른 저장소, 다른 Windows 파일, 버전 불일치, SHA-256 누락 또는 변경된 파일 정보는 거부합니다.
- 연결된 클라이언트는 인증된 호스트의 전용 경로를 사용합니다. 수동 확인은 호스트에도 강제 새로고침을 전달합니다. 일반 배포 목록과 파일은 별도 경로를 유지합니다.
- 설치 파일을 검증한 뒤 Inno Setup이 기존 프로세스의 종료를 최대 30초 기다립니다. 기존 파일을 임시 백업하고 설치 후 원래 데이터 경로로 다시 실행합니다. 설치 실패 시 이전 파일 복구를 시도하며, 복구 실패는 수동 복구 안내로 남깁니다.

## 실행한 검사

- `tools/build.ps1`: 두 런타임의 CoreChecks, DesktopChecks, 런타임 간 TLS 전송, 두 배포 대상의 publish 및 Inno 설치 파일 생성 통과.
- 자동·수동 조회 구분, 전용 경로 인증, 카탈로그와 파일 식별 정보 변조 거부, 구버전 호스트 안내, 기본 설정·알림 기록 유지, 트레이 메뉴 활성화, 요청 시 다운로드 검사 통과.
- 설치 파일의 해시·제품 리소스, 설치 등록 경로, 실제 PID 이미지, 한글·공백·앰퍼샌드 경로 인용, 결과 파일의 일회성 소비 검사 통과.
- 실제 250% DPI와 100/125/150/200/250% 배율을 모사한 레이아웃 검사 통과. 모사 검사는 실제 모니터 DPI 변경과 다릅니다. 설정 창의 업데이트 항목도 이미지로 확인했습니다.
- 최종 Inno 수정 후 두 설치 파일을 다시 컴파일했습니다. `FileCopy` 이름 변경 권고 힌트 외에 컴파일 오류는 없습니다.
- GitHub의 작은 가상 화면에서는 900×650 논리 픽셀을 표현할 수 없는 고배율 모사를 사유와 함께 건너뜁니다. 실제 배율 검사는 항상 실행하며, 이 PC에서는 모든 모사 배율을 통과했습니다. 화면 제한으로 줄어든 창을 의도한 크기의 고배율 검사로 기록하지 않습니다.

## 현재 PC의 실제 설치

- 기존 설치된 0.2.2를 새 0.3.0 설치 파일의 자체 업데이트 인계 방식으로 업그레이드했습니다.
- 원래 앱을 종료하지 않는 시험에서 30초 뒤 설치가 중단되었고 기존 프로세스가 유지됐습니다.
- 프로세스가 빠르게 종료되지만 핸들이 남아 있는 경우의 초기화 오류를 실제 시험에서 발견·수정했습니다. 동일 시험을 다시 실행해 설치와 자동 재실행에 성공했습니다.
- 설치 전 백업 및 설치 성공 로그와 재시작 후 `Status=succeeded` 결과 소비를 확인했습니다.
- 설치된 465개 파일의 SHA-256이 최종 로컬 publish 결과와 일치했습니다.
- 기존 등록 프로그램 19개와 설정 JSON이 바이트 단위로 그대로 유지됐습니다.

로컬 증거는 무시된 `artifacts/`의 `build-0.3.0-final.log`, `inno-*-0.3.0.log`, `self-update-timeout-0.3.0.log`, `self-update-installed-0.3.0.json`에 남깁니다. 개인 설정과 연결 정보는 Git에 포함하지 않습니다.

## 공개 릴리스 및 실제 전송

- 공개 저장소: [yunhyok/ProgramManager](https://github.com/yunhyok/ProgramManager), 기본 브랜치 `main`.
- [v0.3.0 릴리스](https://github.com/yunhyok/ProgramManager/releases/tag/v0.3.0)는 `4cada227a8d1cf3167ed7a75b96c094ecea41bd6`에서 생성됐으며 [GitHub 빌드·릴리스 작업](https://github.com/yunhyok/ProgramManager/actions/runs/34441766168)이 성공했습니다.
- CI는 실제 화면 배율과 100% 모사를 검사했습니다. 작은 가상 화면에 담을 수 없는 125/150/200/250% 모사는 각각 SKIP 사유를 기록했습니다. 로컬에서는 두 런타임 모두 생략 없이 전체 배율을 통과했습니다.
- 공개 GitHub에 인증 없이 접속해 실제 설치 파일을 받았고, 인터넷 HTTP 요청을 실패시키는 클라이언트에서도 인증된 로컬 호스트를 통해 같은 파일을 받았습니다. 두 파일의 제품·버전 정보와 SHA-256을 검사했습니다. 두 번째 물리 PC를 사용한 시험은 아닙니다.
- Windows 7용 실제 릴리스 설치 파일도 별도로 다운로드해 제품·버전·해시를 검사했습니다.
- 현재 설치 버전 0.3.0은 업데이트 대상으로 제안되지 않았습니다. 설치된 앱의 실제 접근성 트리에서도 제목 `Program Manager 0.3.0`, 등록 19개, 업데이트 완료 상태를 확인했습니다.

| 공개 파일 | 바이트 | SHA-256 |
| --- | ---: | --- |
| ProgramManager-Setup-0.3.0.exe | 51059132 | `03b1bb3e7d116da91e45f6a2669155b1954b3d4771c6d32a38002ea20a1e8f05` |
| ProgramManager-Setup-0.3.0-win7.exe | 2419391 | `53a3a3ed96626c7623f5fe5e8cdf65524c2330c54a0c47489e0c449665b03771` |

공개 `SHA256SUMS.txt`도 다운로드해 위 검증 결과와 비교했습니다. CI 설치 파일은 CI 런타임과 컴파일러로 빌드하므로 앞서 설치한 로컬 빌드 파일과 바이트가 다를 수 있습니다. 공개 파일 전송 증거는 `artifacts/self-update-live/live-update-verification.json`에 남깁니다.

## 확인 범위

실제 Windows 7 PC와 두 번째 물리 PC에서 설치한 결과는 아닙니다. Windows 7 대상은 .NET Framework 4.8 빌드·실행과 별도 설치 파일로 검사했습니다. Windows 알림 정책이 실제 말풍선을 표시하는지와 설치 중 강제 디스크 오류 뒤 파일 복구는 실기기 시험에 포함하지 않았습니다. 새 버전 알림 조건·기록과 트레이 메뉴는 실행 검사로 확인했습니다.
