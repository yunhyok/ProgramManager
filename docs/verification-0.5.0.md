# Program Manager 0.5.0 검증 기록

호스트의 배포 가능 여부가 서로 다른 원인을 모두 설치 파일 없음으로 표시하던 문제를 수정했습니다. 저장소별 **시험판 포함**과 **ZIP 다운로드**를 추가했습니다. 설치 EXE/MSI와 ZIP 다운로드 가능 여부를 구분하고, 릴리스 없음·초안·시험판 제외·버전 태그·첨부 파일·패턴·후보 중복을 실제 원인에 맞게 표시합니다.

## 판정과 전송

같은 시점에 조회한 94개 실제 저장소의 릴리스 메타데이터를 수정 전후 코드로 비교했습니다. 이전 코드는 21개를 허용했고, 수정 후 기본 설정은 23개, 시험판 포함은 28개를 허용했습니다. 시험판 포함 상태에서 나머지는 릴리스 없음 64개와 여러 배포 파일 중 선택이 필요한 2개였습니다. 이 비교는 메타데이터만 사용했고 실제 사용자의 저장소 선택을 변경하지 않았습니다.

숫자 버전 뒤에 `-rc.1` 또는 `-experimental`이 붙은 태그도 시험판으로 다룹니다. 같은 숫자 버전이면 정식 릴리스를 우선하고, 시험판끼리는 최근 게시본을 선택합니다. Windows 설치 버전은 숫자만 비교하므로 같은 숫자 버전의 시험판 교체는 직접 다시 설치하거나 다운로드해야 합니다. 원래 태그와 시험판 표시는 설명과 이력에 남깁니다.

ZIP은 기존 파일 크기·SHA-256·인증된 TLS 전송 경로를 재사용합니다. 경고창 확인 후 실제 Windows 다운로드 폴더의 별도 임시 폴더에서 검증하고, 원래 파일 이름으로 옮깁니다. 기존 이름이 있으면 번호를 붙입니다. 자동 실행·압축 해제·설치·프로그램 등록은 하지 않습니다. 구형 클라이언트에는 ZIP을 제외한 유효한 목록과 업데이트 안내를 반환합니다.

공개 GitHub의 실제 ZIP(33,677 bytes)도 별도 검증 호스트를 거쳐 클라이언트로 받았습니다. 원본 메타데이터의 크기·SHA-256과 일치했고 파일은 실행하지 않았습니다. 실제 앱의 설정과 등록 목록은 변경하지 않았습니다.

## 검사와 리뷰

- .NET 8과 .NET Framework 4.8 코어·데스크톱 검사 및 양방향 런타임 전송 검사 통과.
- 시험판 옵션의 기본값·저장·즉시 재판정, 해제 후 통신 실패 시 이전 시험판 제거, 정식 우선순위, 제외된 시험판의 잘못된 메타데이터 격리 확인.
- 설치 파일 우선 선택, ZIP 패턴 지정, 여러 ZIP 후보의 명시적 선택, Windows 11/net48 및 Win7/Win11 공용 파일 판정 확인.
- ZIP 경고창 취소 시 무동작, 실제 TLS 테스트 호스트에서 다운로드 성공, 등록 목록 불변, 파일 이름·경로 검증, 이름 충돌 시 기존 파일 보존 및 임시 폴더 정리 확인.
- ZIP 미지원 클라이언트와 0.2.0 이전 클라이언트의 안내·호환성 확인.
- 실제 배율 및 100/125/150/200/250% 모의 배율 검사 통과. 로컬 검사에서 건너뛴 배율 없음. 제품 폼 렌더링에서 새 시험판 열과 원인별 안내 확인.

호스트 UI와 클라이언트 ZIP 동작은 별도 작업자가 구현했고 독립 리뷰를 거쳤습니다. 리뷰에서 확인한 시험판 해제 시 캐시 처리, 구형 클라이언트의 ZIP 전용 목록 처리, 같은 숫자 버전의 정식/시험판 우선순위 예외를 수정하고 회귀 검사를 추가했습니다. 최종 리뷰에 남은 P1/P2 지적은 없습니다. Windows 7 실기기 검증 결과는 아닙니다.

로컬 증거는 `artifacts/build-0.5.0.log`, `artifacts/core-final-net8.log`, `artifacts/core-final-net48.log`, `artifacts/layout/`, `artifacts/release-audit/`, `artifacts/live-zip/output/verification.json`에 있습니다. 실제 저장소 원본 메타데이터와 사용자 설정 백업은 저장소에 게시하지 않습니다.

## 배포와 설치

제품 커밋은 `432f2f1781597dbf43939fc66d286bf9e682fe0c`입니다. [태그 CI 35315254404](https://github.com/yunhyok/ProgramManager/actions/runs/35315254404)와 [main CI 35315254149](https://github.com/yunhyok/ProgramManager/actions/runs/35315254149)가 최종 소스로 전체 검사와 두 설치 파일 생성을 완료했습니다. [v0.5.0 릴리스](https://github.com/yunhyok/ProgramManager/releases/tag/v0.5.0)에 설치 파일과 `SHA256SUMS.txt`를 게시했습니다.

공개 자산을 다시 다운로드하여 매니페스트 및 GitHub 자산의 크기·SHA-256과 대조했습니다.

| 대상 | 파일 크기 | SHA-256 |
| --- | ---: | --- |
| Windows 10/11 | 51,276,339 bytes | `501a79ef029f6a4b3146cd26d2e5205cfba486d47a4f8e8d92542692741f0f22` |
| Windows 7/8 | 2,643,790 bytes | `97fbfde77639e6d2c210189ef6fbffb6387b9b8528c1c4dbccc4d3cfc86c4738` |

현재 PC에 공개 설치 파일을 적용했습니다. 이전 설치 파일 백업과 성공 결과, 정상 재시작, 제품 버전 `0.5.0+432f2f1781597dbf43939fc66d286bf9e682fe0c`를 확인했습니다. 등록 프로그램 19개, 저장소 선택 10개 및 각 옵션, 실행 경로와 연결 설정이 보존됐습니다. 저장소의 시험판 옵션을 임의로 켜거나 배포할 저장소를 추가하지 않았습니다.

설치본의 접근성 정보에서 업데이트 완료 상태, 프로그램 수와 호스트 관리 탭을 확인했습니다. 저장소 선택 버튼의 실제 UI 클릭은 Windows 도구의 `coordinate input geometry is unavailable` 오류로 실행되지 않아, 해당 대화상자의 동작 검증에는 위 제품 폼 기반 자동 검사를 사용했습니다.
