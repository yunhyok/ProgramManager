# Program Manager 0.2.0 · GitHub 배포 안내

GitHub에 릴리스를 올리는 작업은 기존 개발 과정대로 진행합니다. Program Manager의 호스트는 그중 배포할 저장소를 선택하고, 클라이언트가 요청한 설치 파일과 설명을 내부망으로 제공합니다.

```text
GitHub Releases ── 목록 확인 / 필요한 파일 받기 ──▶ 호스트 PC
                                                     │
                              내부망: 목록 · 설치 파일 · 설명 HTML
                                                     ▼
                                             클라이언트 PC
                                           (인터넷 연결 불필요)
```

## 1. 호스트에서 배포할 저장소 선택

1. **호스트 관리 → 호스트 켜기**를 누릅니다. **설정**에서도 호스트 역할과 다른 PC가 접근할 주소·포트를 변경할 수 있습니다.
2. **호스트 관리 → GitHub 설정**에서 사용할 계정을 연결합니다. 호스트에 GitHub CLI가 로그인되어 있으면 기존 인증을 사용할 수 있습니다. 또는 토큰을 입력합니다. 비공개 저장소는 해당 저장소와 릴리스를 읽을 수 있는 권한이 필요합니다.
3. **저장소 선택**에서 배포할 저장소를 고르고 **선택한 저장소 동기화**를 누릅니다. 메타데이터를 바로 가져오며, 모든 Release 설치 파일을 다운로드하지 않습니다.
4. 이후 새 버전은 **GitHub 동기화**로 확인합니다. 다른 PC에서는 **연결 코드**를 등록해 이 호스트의 배포 카탈로그를 사용합니다.

GitHub 로그인과 토큰은 호스트에서만 필요합니다. 직접 입력한 토큰은 Windows 사용자 계정으로 보호해 저장하며, 연결 코드·클라이언트 목록·설명 HTML에 포함하지 않습니다. 연결 코드 자체는 호스트 접근 권한을 포함하므로 사용할 PC에만 전달하세요.

**GitHub 설정의 로그인 방식**은 이미 로그인해 둔 PC에서는 **기존 GitHub CLI 로그인 사용**을 선택하면 됩니다. 토큰 방식은 선택한 저장소의 Contents 읽기 권한을 사용합니다. **공개 저장소만 (로그인 없음)**을 선택할 때는 GitHub 계정 또는 조직 이름을 입력하세요. 비공개 저장소는 이 방식으로 조회할 수 없습니다.

## 2. 릴리스와 Windows별 설치 파일

배포 대상은 GitHub의 정식 **Releases**에 첨부된 EXE/MSI입니다. 태그는 `v1.2.3`, `1.2.3`처럼 숫자 버전이어야 합니다. 소스 코드의 커밋이나 태그만 있고 Release 설치 파일이 없으면 설치할 수 없습니다. Draft와 Prerelease는 제외됩니다. 조회한 최근 100개 Release 중 정식 버전을 최대 30개 가져오므로 전체 과거 릴리스 보관 기능은 아닙니다.

예를 들어 같은 저장소의 `v1.5.0` Release에 다음 두 파일을 올릴 수 있습니다.

| 파일 예시 | 대상 |
| --- | --- |
| `MyTool-Setup-1.5.0.exe` | Windows 10/11 64비트 |
| `MyTool-Setup-1.5.0-win7.exe` | Windows 7 계열 |

자동 선택 결과가 하나로 결정되지 않으면 **저장소 선택**에서 Windows별 파일 이름 패턴을 지정합니다. 파일 이름을 일정하게 유지하면 관리하기 쉽습니다. 패턴은 같은 플랫폼의 파일 후보가 하나로 좁혀지도록 지정하세요. **파일 이름만 바꿔도 OS 호환성이 생기는 것은 아닙니다.** 각 파일은 해당 OS에서 실행 가능한 설치본이어야 합니다.

패턴은 대소문자를 구분하지 않으며 `*`는 여러 글자, `?`는 한 글자를 뜻합니다. 파일명에 `win10`과 `win7`이 각각 들어 있다면 현대 Windows용은 `*win10*.exe`, Windows 7용은 `*win7*.exe`처럼 지정합니다. `*.exe`처럼 넓은 패턴은 두 파일에 동시에 일치할 수 있습니다. 자동으로 올바르게 선택된다면 패턴은 비워 두세요.

Windows별 릴리스는 독립적으로 찾습니다. 새 버전에 Windows 10/11용만 있고 Windows 7용은 이전 버전까지 제공되었다면, Windows 7 PC에는 사용할 수 있는 Windows 7용 버전이 기준이 됩니다. 맞는 배포본이 없으면 다른 OS용 설치 파일을 대신 사용하지 않습니다.

ZIP 형태의 포터블 앱, 소스 ZIP/TAR와 GitHub Actions 아티팩트는 이번 버전의 설치 대상이 아닙니다. 이 앱들은 **내 프로그램**에서 기존 실행 파일을 계속 사용할 수 있습니다.

## 3. 클라이언트에서 설치·업데이트

1. Program Manager **0.2.0 이상**에서 **설정**에 연결 코드를 등록하고 **배포 카탈로그 → 목록 새로고침**을 선택합니다. GitHub 배포 카탈로그는 0.1.x 클라이언트에서 사용할 수 없습니다.
2. 프로그램을 고르고 **오프라인 설명**을 확인합니다. 호스트는 README와 릴리스 이력을 받아 자체 포함 HTML로 전달합니다.
3. **설치 / 업데이트**를 선택하고 설치를 확인합니다. 이어서 호스트가 필요한 파일을 내려받거나 캐시를 재사용해 전송합니다. 클라이언트는 파일 크기와 SHA-256 검증을 통과한 뒤 설치 프로그램을 실행합니다.
4. 설치 프로그램의 안내를 따르고, 설치가 끝나면 실행 경로를 확인합니다. 기존 실행 경로가 유효하면 유지합니다. 확인된 설치 결과가 **내 프로그램**에 반영됩니다.

첫 요청은 GitHub에서 파일을 받는 시간이 추가될 수 있습니다. 다음 요청부터는 유효한 캐시가 있으면 재사용합니다. 설치 프로그램이 관리자 권한을 요청할 수 있으며, 취소·실패를 설치 성공으로 기록하지 않습니다.

이미 설치된 앱은 **기존 설치 연결**로 배포 항목에 연결할 수 있습니다. 현재 버전을 모르면 비워 두세요. 목록의 최신 버전과 설치된 버전이 같다고 자동 가정하지 않습니다.

## 4. 인터넷과 캐시

| 상황 | 가능한 작업 |
| --- | --- |
| 클라이언트 인터넷 없음, 호스트 인터넷 있음 | 목록·설명 확인과 설치·업데이트 가능 |
| 호스트 인터넷 없음, 요청한 파일이 캐시에 있음 | 내부망 연결이 되고 유효한 캐시가 있으면 해당 파일 제공 가능 |
| 호스트 인터넷 없음, 요청한 파일이 캐시에 없음 | 다운로드 불가. 호스트 인터넷 복구 후 다시 요청 |
| 호스트가 꺼져 있거나 Manager가 종료됨 | 새 요청 불가. 클라이언트에 이미 설치된 앱은 계속 실행 가능 |

README와 릴리스 이력의 **본문**은 외부 리소스를 요구하지 않는 HTML로 제공합니다. 제목·본문·코드 블록을 표시하며, 복잡한 Markdown 서식과 링크는 텍스트로 남습니다. 별도 설명 사이트, 첨부파일과 외부 이미지를 모두 미러링하는 기능은 아닙니다. 오프라인에서 반드시 필요한 사용법은 README나 릴리스 본문에도 텍스트로 작성하세요.

도움말과 오프라인 설명은 Program Manager 안에서 열립니다. 별도의 브라우저가 필요하지 않으며, 이 화면에서는 외부 사이트로 이동하지 않습니다.

**설명 / 이력**은 이미 동기화한 메타데이터를 표시하며 README를 받지 않습니다. **오프라인 설명**을 열 때 HTML을 요청합니다. 설명 캐시는 날짜가 바뀌어도 재사용하며, 동기화한 프로그램·릴리스 정보가 바뀌거나 캐시가 정리되면 다음 요청 때 새로 만듭니다. README만 수정했다면 **임시 파일 정리** 후 **오프라인 설명**을 다시 여세요.

임시 파일은 기본적으로 **마지막 사용 후 7일**이 지나면 정리합니다. 보관 기간은 **GitHub 설정**에서 1~30일로 정합니다. Program Manager 시작 시와 실행 중 매시간 정리하며, **임시 파일 정리** 버튼은 사용 중인 파일을 건너뜁니다. 앱을 종료해 둔 동안에는 정리 작업도 실행되지 않습니다. 정리된 파일은 다음 요청 때 다시 받을 수 있습니다.

호스트 캐시는 `%LOCALAPPDATA%\ProgramManager\repository\temp`, 클라이언트 임시 파일은 `%LOCALAPPDATA%\ProgramManager\temp`에 둡니다. 정리는 앱이 관리하는 임시 설치 파일과 설명 캐시만 대상으로 합니다. 등록된 실행 목록, 설치된 프로그램, GitHub 저장소 선택과 릴리스 메타데이터는 유지됩니다. Windows 전체 Temp 폴더를 삭제하지 않습니다.

## 5. 이전 방식에서 전환

**내 프로그램**의 기존 0.1.x 실행 목록은 계속 사용합니다. 새 GitHub 저장소를 선택한다고 이미 설치된 앱을 다시 설치하거나 실행 파일을 이동하지 않습니다.

새 배포는 GitHub 저장소와 Releases를 기준으로 관리합니다. 프로그램 이름이 같다는 이유만으로 기존 로컬 항목과 자동 결합하지 않습니다. **기존 설치 연결**에서 실행 경로와 설치 버전을 확인해 연결하세요.

## 자주 막히는 부분

| 증상 | 다음 행동 |
| --- | --- |
| 저장소가 목록에 없음 | GitHub 계정·소유자와 비공개 저장소 접근 권한을 확인하고 목록을 다시 불러옵니다. |
| 저장소는 있지만 설치할 버전이 없음 | 정식 Release에 EXE/MSI가 첨부되어 있는지 확인합니다. 소스 ZIP만 있거나 Draft/Prerelease이면 배포되지 않습니다. |
| 파일을 하나로 선택할 수 없음 | 저장소별 Windows 대상 파일 이름 패턴을 지정해 후보를 하나로 줄입니다. |
| Windows 7 PC에 새 버전이 없음 | 해당 버전에 Windows 7용 설치 파일이 있는지 확인합니다. 현대 Windows용 파일을 대신 지정하지 않습니다. |
| GitHub 권한·요청 한도 오류 | 호스트의 인증 상태와 저장소 읽기 권한을 확인합니다. 요청 한도 오류면 안내된 시간 후 동기화를 다시 실행합니다. |
| 목록은 보이는데 설치 파일을 받을 수 없음 | 호스트의 GitHub 연결과 캐시 상태를 확인합니다. 목록이 저장되어 있어도 설치 파일이 미리 받아져 있다는 뜻은 아닙니다. |
| 호스트에 연결할 수 없음 | 호스트 실행·절전 상태, 연결 코드의 주소·포트, 내부망 연결과 방화벽을 확인합니다. 기본 TCP 포트는 `45672`입니다. |
| 설명에서 링크·표가 원문 문자로 보임 | 오프라인 HTML은 제목·본문·코드 블록 중심으로 표시합니다. 외부 링크는 자동으로 열리지 않습니다. 원문 URL로 접근하려면 인터넷 연결이 필요합니다. |

화면별 작업 순서는 [오프라인 도움말](guide.html)에 있습니다. 현재 버전의 검증 결과는 별도 빌드 로그를 확인하세요. 이 문서는 기능 사용법이며 실제 Windows 7 PC의 검증 완료를 의미하지 않습니다.
