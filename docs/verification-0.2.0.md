# Program Manager 0.2.0 검증 기록

검증일: 2026-09-10. Windows 10 Pro 64비트(10.0.19045), 실제 배율 250%(240 DPI), .NET SDK 8.0.425 및 .NET Framework 4.8.

## 변경과 확인 항목

- 호스트에서 GitHub 저장소를 선택하고 숫자 버전의 정식 Release 메타데이터만 동기화합니다. Windows 10/11용과 Windows 7용 설치 파일은 독립적으로 찾습니다.
- 실제 `yunhyok` 계정의 GitHub CLI 로그인을 사용해 접근 가능한 저장소 90개와 비공개 MiniBrowser 저장소를 확인했습니다. 토큰은 검증 로그에 출력하지 않았습니다.
- 별도 데이터 폴더에서 IntraDrop과 MiniBrowser를 선택했습니다. 동기화 직후 설치 파일과 설명 캐시가 비어 있음을 확인했습니다. 실제 사용자 설정의 배포 저장소 선택은 바꾸지 않았습니다.
- 실제 GitHub → 호스트 캐시 → 인증된 TLS 클라이언트 경로로 아래 설치 파일을 내려받고 GitHub 제공 SHA-256과 비교했습니다. 내려받은 다른 프로그램의 설치 파일은 실행하지 않았습니다.

| 프로그램 | 버전 | 대상 | 검증한 크기 |
| --- | --- | --- | ---: |
| IntraDrop | 1.6.2 | Windows 10/11 | 47,746,611바이트 |
| IntraDrop | 1.6.2 | Windows 7 | 2,488,220바이트 |
| MiniBrowser (비공개) | 0.2.1 | Windows 10/11 | 133,387,156바이트 |

두 저장소의 README와 릴리스 이력을 HTML로 받아 UTF-8, CSP 및 외부 스크립트·이미지가 없는 구성을 확인했습니다. 이후 호스트의 GitHub 제공자를 분리해 캐시된 설치 파일과 설명이 계속 전달되는지 확인했습니다. 캐시 정리 후 다시 요청하면 GitHub에서 재다운로드했습니다.

실제 전송 증거: `artifacts/github-live-0.2.0.log`, `artifacts/github-live-result/verification.json`.

## 자동 회귀 검사

`tools/build.ps1`이 제품 빌드, 두 런타임의 Core/데스크톱 검사, UI 크기 검사, 런타임 간 양방향 TLS 통신 검사, 두 설치 파일 생성을 실행합니다.

- 배포 파일 ID·저장소·태그·Windows 대상·버전·파일명·크기·해시 변경 거부, 수신 중 손상·취소 정리, 구형 클라이언트 안내.
- 메타데이터 동기화의 원자적 저장, Windows별 파일 패턴과 모호한 후보 거부, 지연 다운로드, 중복 요청과 사용 중 캐시 보호.
- 외부 다운로드 주소 제한과 인증 헤더 보호, 설명 HTML의 이스케이프 및 무결성.
- GitHub 연결을 교체해도 시작된 설치 파일·README·여러 페이지 메타데이터 요청은 완료 후 해제. 교체된 연결에서 새 요청은 거부.
- 공유 잠금이 풀리면 제한 재시도로 원자적 파일 교체 성공. 영구 잠금이면 기존 파일·설정·바로가기를 보존하며 실패.
- 기존 로컬 등록과 새 GitHub 설정 저장·재로딩, 접근할 수 없어진 기존 저장소 선택 보존, 설치 확인 후 배포 자산 변경 거부.

## UI와 도움말

제품의 실제 폼 소스를 이용해 내 프로그램, 배포 카탈로그, 호스트 관리, 프로그램 등록, GitHub 설정, 저장소 선택, 일반 설정, 연결 코드, 설명/이력, HTML 도움말의 10개 화면을 검사합니다. 각 런타임의 실제 배율과 100·125·150·200·250% 모의 크기를 합쳐 120개 화면입니다. 모의 검사는 프로세스 안에서 글꼴·컨트롤 크기와 창 크기를 조절하며 Windows 표시 설정을 바꾸지 않습니다.

검사는 표 제목·행과 안내 문구의 크기, 버튼 접근성, 도구 모음 줄바꿈, 빈 목록과 다른 Windows 선택 시 버튼 상태를 확인합니다. 첫 열 머리글은 WinForms의 권장 크기가 테두리를 작게 계산하는 경우가 있어 여유 2픽셀을 반영했습니다. 권장 크기뿐 아니라 실제 그려지는 글자 영역도 비교해 말줄임을 검사합니다. 이미지는 실제 폼의 `DrawToBitmap` 결과입니다. 결과는 `artifacts/layout/net8`, `artifacts/layout/net48`에 있습니다.

도움말은 화면별 용도, 호스트·클라이언트 시작 순서, Windows별 파일 예시, 다운로드·정리 기준, 오류별 다음 행동과 데이터 보관을 설명합니다. 현재 탭에 해당하는 도움말 위치를 열며 설치에 HTML 한 파일로 포함합니다. 문서의 UTF-8, 내부 앵커와 외부 리소스 없는 구성을 검사했습니다.

현재 PC의 HTML 연결 프로그램 `MiniBrowserHTML`로 파일을 열면 응용 프로그램을 찾을 수 없었습니다. 도움말과 배포 설명은 기본 브라우저 연결에 의존하지 않는 내장 Windows HTML 보기 창으로 변경했습니다. 실제 도움말의 DOM·본문·선택한 앵커 로딩과 외부 URL 이동 차단을 검사하고 HTML 화면도 렌더링해 확인했습니다. 보기 창은 화면 배율에 맞춰 본문도 확대합니다.

## 설치 결과

현재 PC의 기존 0.1.1을 최종 Windows 10/11 설치 파일로 0.2.0으로 업데이트했습니다. 설치 종료 코드 0이며 설치된 465개 파일의 해시가 최종 게시 폴더와 일치합니다. 설치 전후와 새 앱 실행 후의 설정 파일이 바이트 단위로 동일하고, 등록된 프로그램 19개를 보존했습니다. 설치본의 창 제목 `Program Manager 0.2.0`과 실제 UI의 프로그램 19개 표시를 확인했습니다.

Windows 10/11 설치 파일은 51,041,699바이트, Windows 7용은 2,399,694바이트입니다. 설치 증거는 `artifacts/upgrade-verification-0.2.0.json`, `artifacts/upgrade-0.2.0.log`에 있습니다.

## 확인 범위

Windows 7 실기기와 두 번째 물리 PC, 서로 다른 배율의 모니터 이동은 검사하지 않았습니다. Windows 7용 코드는 이 PC의 .NET Framework 4.8에서 검사했습니다. 인터넷 단절 조건은 클라이언트에 GitHub 접근 코드를 두지 않고 호스트의 GitHub 제공자를 분리하는 방식으로 확인했습니다.

설명 HTML은 README·릴리스 본문을 읽기 위한 페이지입니다. 외부 사이트·이미지·첨부파일 전체 미러링, 모든 Markdown 서식 재현은 포함하지 않습니다.

이 프로젝트에는 GitHub 원격 저장소가 설정되어 있지 않아 원격 CI·Release 게시를 수행하지 않았습니다. 빌드 로그는 `artifacts/build-0.2.0.log`, 설치 파일 해시는 `artifacts/installers/SHA256SUMS.txt`에 있습니다.
