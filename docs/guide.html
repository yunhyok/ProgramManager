Program Manager 0.2.1 사용 안내

이 PC의 프로그램은 한 목록에서 실행하고, 다른 PC에는 GitHub의 배포 버전을 전달합니다.

이미 등록한 프로그램은 그대로 사용하면 됩니다. 새 배포는 호스트에서 GitHub 저장소를 선택하는 방식입니다. 클라이언트 PC에는 GitHub 계정이나 인터넷 연결이 필요하지 않습니다.

도움말과 오프라인 설명은 Program Manager 안에서 열립니다. 별도의 브라우저가 필요하지 않으며, 문서 안의 목차로 이동할 수 있습니다.

기존 프로그램을 실행하고 목록 정리하기

  1. 내 프로그램에서 기존 항목을 선택하고 실행합니다. 업데이트 후에도 등록한 실행 경로는 유지됩니다.
  2. 추가할 앱이 있으면 + 프로그램 등록에서 이름과 실행 파일(.exe) 또는 바로가기(.lnk)를 선택합니다. 버전을 모르면 비워 두세요.
  3. 잘못된 경로는 편집으로 바꾸고, 목록만 정리하려면 목록에서 제거를 사용합니다. 이 작업은 대상 앱을 제거하지 않습니다.

바로가기는 Manager의 데이터 폴더에 복사합니다. 등록한 항목이 실행되는지 확인한 후 바탕화면 바로가기를 정리해도 됩니다. 대상 EXE 파일은 원래 설치 위치에 두세요.

창의 ×를 누르면 트레이에 남습니다. Windows 오른쪽 아래 아이콘을 클릭하면 다시 열립니다. 보이지 않으면 숨겨진 아이콘 영역을 확인하세요. 완전히 종료하려면 트레이 메뉴의 종료를 선택합니다.

최근 프로그램 바로 실행: 트레이 아이콘을 오른쪽 클릭하면 메뉴 맨 위에 최근 실행한 등록 프로그램이 최대 5개 표시됩니다. 원하는 항목을 클릭하면 바로 실행합니다. 중복 없이 가장 최근 실행한 항목부터 표시하며, Manager를 다시 실행해도 유지됩니다.

Manager에서 실행한 기록만 사용합니다. 과거 실행 이력을 자동으로 가져오지 않으므로 처음에는 최근 목록이 비어 있습니다. 등록 이름·실행 경로를 편집하면 최근 항목에도 반영되고, 등록을 제거한 항목은 최근 목록에서도 사라집니다.

호스트 시작 · 3단계

인터넷이 연결된 개발 PC에서 진행합니다. 같은 Program Manager 앱을 사용합니다.

  1. 호스트 켜기
    호스트 관리 → 호스트 켜기를 누릅니다. 설정에서 역할과 다른 PC가 접근할 이 PC의 배포 주소·포트를 확인하거나 변경할 수 있습니다. 기본 TCP 포트는 45672입니다.
  2. GitHub 연결 후 저장소 동기화
    GitHub 설정에서 이 PC의 GitHub CLI 로그인 또는 직접 입력한 토큰을 사용합니다. 저장소 선택에서 배포할 저장소를 고르고 선택한 저장소 동기화를 누르면 메타데이터를 바로 가져옵니다. 이후 새 버전은 GitHub 동기화로 확인합니다.
  3. 클라이언트에 연결 코드 전달
    연결 코드를 사용할 PC에 전달합니다. 이제 클라이언트가 요청한 설치 파일과 설명을 호스트가 받아 전달합니다. 호스트 PC에서도 배포 카탈로그를 이용할 수 있습니다.

완료 확인: 호스트 목록에 선택한 저장소와 배포 가능한 버전이 표시되고, 클라이언트가 목록을 새로 고쳤을 때 같은 프로그램이 보이면 준비되었습니다. 이 단계에서 모든 설치 파일을 다운로드하지 않습니다.

비공개 저장소는 해당 저장소를 읽을 수 있는 계정·토큰으로 연결해야 합니다. GitHub 인증 정보는 호스트에서만 사용합니다. 클라이언트에 토큰을 복사할 필요가 없습니다.

로그인 방식 선택: 이미 GitHub CLI로 로그인한 PC는 기존 GitHub CLI 로그인 사용을 선택합니다. 토큰은 선택한 저장소의 Contents 읽기 권한이 필요합니다. 공개 저장소만 (로그인 없음)을 선택할 때는 GitHub 계정 또는 조직 이름을 입력하세요.

호스트가 파일을 제공하려면 사용자가 로그인해 있고 Program Manager가 실행 중이어야 합니다. 트레이에 두어도 됩니다. 종료·로그아웃·절전 중에는 새 요청에 응답하지 못합니다.

클라이언트 시작 · 3단계

프로그램을 사용할 PC에서 진행합니다. 호스트와 내부망으로 연결되어야 하며, GitHub 배포에는 클라이언트도 Program Manager 0.2.0 이상이 필요합니다.

  1. 호스트 연결
    설정에서 클라이언트 역할을 선택하고 호스트에서 받은 연결 코드를 등록합니다. 배포 카탈로그 → 목록 새로고침을 누릅니다.
  2. 프로그램과 설명 확인
    프로그램을 선택하고 오프라인 설명을 엽니다. 호스트가 README와 릴리스 이력을 HTML로 전달하므로 본문은 인터넷 없이 읽을 수 있습니다. 설치는 이 PC의 Windows에 맞는 파일을 사용합니다.
  3. 설치 후 실행 경로 확인
    설치 / 업데이트를 누르고 설치를 확인합니다. 다운로드와 크기·SHA-256 검증을 통과하면 설치 프로그램이 실행됩니다. 안내에 따라 설치를 마친 후 실제 EXE 또는 바로가기를 확인하면 내 프로그램에서 실행할 수 있습니다.

완료 확인: 설치가 끝난 앱이 내 프로그램에 표시되고 실행으로 열리면 완료입니다. 카탈로그에만 표시되는 상태는 설치 완료가 아닙니다.

이미 설치된 앱은 기존 설치 연결로 실행 경로와 현재 버전을 연결할 수 있습니다. 버전을 모르면 비워 두세요. 새 배포 목록에 있다는 이유만으로 기존 앱을 재설치하지 않습니다.

설치 프로그램이 관리자 권한을 요청할 수 있습니다. 설치 취소·실패는 성공으로 기록하지 않습니다. 업데이트 후 경로가 같으면 기존 경로를 유지하고, 달라졌다면 새 경로를 확인합니다.

버전과 Windows 7용 파일은 어떻게 구분하나요?

버전의 기준은 v1.2.3, 1.2.3 같은 숫자 태그의 GitHub Releases입니다. 브랜치의 최신 소스나 커밋을 설치하는 기능은 아닙니다. Draft와 Prerelease를 제외한 정식 Release의 EXE/MSI 설치 파일을 사용합니다. 조회한 최근 100개 Release 중 정식 버전을 최대 30개 가져옵니다.

예시 파일대상
MyTool-Setup-1.5.0.exeWindows 10/11 64비트용
MyTool-Setup-1.5.0-win7.exeWindows 7 계열용

같은 프로그램이라도 Windows별 설치 파일과 제공되는 최신 버전이 다를 수 있습니다. Windows 7용은 Windows 7용 릴리스에서 선택하며, 맞는 파일이 없으면 다른 OS용으로 대체하지 않습니다.

파일 후보가 여러 개이면 호스트의 저장소 선택에서 Windows별 파일 이름 패턴을 지정해 선택을 명확하게 합니다. 이름을 바꾸는 것만으로 OS 호환성이 바뀌지는 않습니다. ZIP 포터블 앱, 소스 ZIP/TAR와 Actions 아티팩트는 이번 버전의 설치 대상이 아닙니다.

패턴의 *는 여러 글자, ?는 한 글자를 뜻합니다. 예를 들어 파일명에 Windows 구분이 있다면 *win10*.exe와 *win7*.exe를 각각 사용합니다. *.exe처럼 넓은 패턴은 파일을 하나로 구분하지 못할 수 있습니다. 자동 선택이 맞으면 비워 두세요.

설치 파일과 설명은 언제 받고 언제 지우나요?

사용자의 행동호스트의 동작
저장소 선택·GitHub 동기화프로그램과 릴리스 메타데이터를 받습니다. 모든 설치 파일을 미리 받지는 않습니다.
설치 / 업데이트필요한 파일이 캐시에 없으면 GitHub에서 받고 검증한 뒤 클라이언트에 전달합니다. 유효한 캐시는 재사용합니다.
설명 / 이력이미 동기화한 프로그램 설명과 릴리스 정보를 표시합니다. README를 새로 받지 않습니다.
오프라인 설명README와 릴리스 이력을 HTML로 제공합니다. 저장된 설명 캐시가 있으면 재사용합니다.
임시 파일 정리사용 중인 파일을 제외하고 앱의 임시 파일을 정리합니다. 설치된 앱과 목록·설정은 유지합니다.

자동 정리 기본값은 마지막 사용 후 7일이며, GitHub 설정에서 1~30일로 정합니다. 앱 시작 시와 실행 중 매시간 확인합니다. 앱이 종료되어 있으면 정리도 실행되지 않습니다. 삭제된 캐시는 다음 요청 때 다시 받습니다. Windows의 전체 Temp 폴더를 비우지 않습니다.

설명 캐시는 날짜가 바뀌어도 재사용합니다. 동기화한 프로그램·릴리스 정보가 바뀌거나 캐시가 정리되면 다음 요청 때 새로 받습니다. README만 바뀐 경우에는 임시 파일 정리 후 오프라인 설명을 다시 엽니다.

호스트 인터넷이 끊긴 경우: 이미 받은 유효한 파일은 제공할 수 있지만, 아직 받지 않았거나 정리된 파일은 새로 다운로드할 수 없습니다. 목록이 보인다고 설치 파일까지 저장되어 있는 것은 아닙니다.

오프라인 설명의 범위: README와 릴리스 본문을 HTML로 제공합니다. 제목·본문·코드 블록을 표시하며, 복잡한 Markdown 서식과 링크는 텍스트로 남습니다. 외부 설명 사이트·첨부파일·이미지를 모두 내려받지는 않습니다. 원문 URL로 접근하려면 인터넷 연결이 필요합니다.

기본 설치 위치는 %LOCALAPPDATA%\Programs\Program Manager입니다. 시작 메뉴에서 실행하세요. Windows 7 설치에서 런타임 안내가 나오면 .NET Framework 4.8을 먼저 설치합니다. Manager 설치 프로그램이 런타임을 자동 다운로드하지는 않습니다.

설정과 연결 정보

기본 데이터 폴더는 %LOCALAPPDATA%\ProgramManager입니다. 호스트 캐시는 repository\temp, 클라이언트 임시 파일은 temp에 둡니다. 프로그램을 제거해도 사용자 데이터는 보존합니다.

직접 입력한 GitHub 토큰과 연결 정보는 Windows 사용자 계정으로 보호하므로 다른 PC·사용자에게 단순 복사해 이전하지 않습니다. 연결 코드에는 호스트 주소·포트·인증서 지문·공유 비밀이 포함됩니다. 사용할 PC에만 전달하고 공개 문서나 스크린샷에 넣지 마세요.

클라이언트는 TLS 1.2에서 등록된 인증서 지문으로 호스트를 확인합니다. --tray는 트레이 시작, --data-dir "폴더 경로"는 별도 데이터 폴더 실행 옵션입니다. 일반 사용에서는 기본 경로를 사용하면 됩니다.

원격 무인 설치, 자동 롤백, 호스트 자동 검색, Windows 서비스와 인터넷 중계는 제공하지 않습니다. 실제 Windows 7 PC와 두 번째 물리 PC에서의 설치·통신 검증은 별도입니다.
